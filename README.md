# NocoBase 插件：附件智能清理与生命周期管理 (Plugin Attachment Cleaner)

`@nocobase/plugin-attachment-cleaner` 是专为 NocoBase 2.x 设计的企业级附件全生命周期管理插件。通过深度遍历业务表引用关系，智能扫描孤立（未引用）附件与重复冗余文件，提供多级安全隔离回收站、智能去重合并、自动化定时物理清理与完备的操作审计日志，助力企业大幅降低对象存储与磁盘成本。

---

## 🌟 核心特性

### 1. 🔍 全库附件深度分析与智能扫描 (Deep Scan & Analysis)
- **业务引用关系反向穿透**：全自动扫描全库所有数据表（Collections）及所有附件字段（Attachment Field），精确建立文件引用映射拓扑。
- **孤儿/闲置附件识别 (Orphaned Attachments)**：精准检测由于业务记录被删除、字段清空、图片替换等原因遗留在存储中的无主附件。
- **重复文件指纹识别 (Duplicate Detection)**：基于文件特征智能分组识别完全相同的冗余文件，计算潜在可节省的存储容量。
- **存储概览大盘**：实时统计全站总附件数量、总存储空间占用、未引用附件占用及回收站占用。

### 2. 🛡️ 多级安全隔离机制与回收站 (Recycle Bin)
- **非破坏性软隔离**：检测到的未引用孤立附件不会被直接物理删除，而是安全移入“附件回收站”，保障业务零风险。
- **一键无损还原**：回收站文件支持随时一键撤销并还原回原始附件库，恢复正常访问。
- **单条/批量彻底擦除 (Purge)**：在确认无误后，支持手动对回收站中的文件进行物理擦除，释放底层磁盘或云对象存储（Local / OSS / S3 / COS）空间。

### 3. ⚡ 智能去重与引用重定向 (Smart Deduplication)
- **保留策略定制**：支持针对重复附件组指定“优先保留的存储空间 (Preferred Storage)”或按引用频次/创建时间智能决策。
- **全库引用自动重定向**：每组重复附件只保留 1 份主文件，其余副本自动移入回收站，同时**自动更新改写全库所有业务记录中的外键引用**，确保业务数据无缝衔接且不丢失显示。

### 4. ⏰ 自动化定时巡检与生命周期策略 (Scheduled Auto-Cleaning)
- **内置 Cron 调度任务**：每日凌晨（`0 2 * * *`）自动执行超期附件清理任务。
- **灵活保留期配置**：支持自定义回收站保留天数阈值（如默认 30 天），超期文件自动执行物理擦除。
- **支持后台热配置**：无需重启服务即可即时启停自动清理开关或调整保留天数。

### 5. 📜 完备的操作审计与追踪 (Audit Trail)
- **全操作审计记录**：记录扫描分析、移入回收站、还原附件、物理擦除、智能去重等所有关键操作。
- **详细操作快照**：包含操作人、动作类型、影响条数、参数及执行时间。
- **自动滚动裁剪**：内置日志上限自动归档机制，避免审计表无限膨胀。

### 6. 💻 现代化可视化管理控制台与 CLI 支持
- **直观易用的前端 UI**：内置仪表盘、未引用列表、重复文件管理、回收站及设置面板。
- **强大的 CLI 命令行**：支持在无头服务器或 CI/CD 流程中通过终端直接触发扫描、清理与去重。

## 🛠️ CLI 命令行指南

在 NocoBase 根目录下，可通过 CLI 工具直接调用附件清理指令：

```bash
# 1. 扫描并输出全库附件分析报告
yarn nocobase attachment-cleaner:scan

# 2. 自动物理擦除回收站中已超期的附件（可选指定天数阈值）
yarn nocobase attachment-cleaner:clean --days 30

# 3. 对全库重复文件执行智能去重并重定向业务引用
yarn nocobase attachment-cleaner:dedup
```

## 📊 数据表模型 (Collections)

插件内置以下系统数据表：

| 数据表标识 (`collection`) | 说明 |
| :--- | :--- |
| `attachmentRecycleBin` | 附件回收站记录表，记录附件 ID、移入时间与操作人 |
| `attachmentCleanerSettings` | 插件全局运行配置表（自动清理开关、保留天数、去重首选存储等） |
| `attachmentCleanerAuditLogs` | 操作审计日志表，持久化记录每一次清理、去重与还原操作 |

## ⚠️ 使用须知

- **物理文件删除机制**：彻底删除（Purge）与超期自动清理通过 NocoBase file-manager 的全局 `afterDestroy` 钩子删除物理文件（Local 直接 unlink，OSS / S3 / COS 调用对应 client）。开启 `paranoid` 的存储会保留文件（平台语义）。请勿在未安装 file-manager 的环境中使用本插件的删除功能。
- **去重安全性**：重复文件判定基于**全文件 SHA-256 内容指纹**；无法读取文件内容的附件（如云存储凭证失效）不参与去重分组，宁可漏判不可误删。去重在后台异步执行，完成后界面自动刷新结果；存在引用更新失败的附件不会被移入回收站（详见审计日志）。
- **原地覆盖的范围**：「上传新文件覆盖」仅在**同一存储空间**内进行（保持附件 ID、URL 与文件名不变，外部引用不断链）；跨存储请使用「全局改指向（引用迁移）」模式。
- **权限**：清理、去重、替换与配置修改仅对管理员角色开放；普通登录用户仅可查看扫描结果与审计日志。
- **快照与分页**：扫描结果快照持久化时最多保留 10000 条（超出时优先保留被标记的附件：未引用 / 重复 / 回收站 / 物理丢失），界面按页加载与搜索，超大附件库也不会拖慢页面。
- **多实例部署注意**：扫描任务状态与去重任务状态保存在进程内存中；PM2 cluster / 多副本部署时请在单一实例上启用定时扫描与自动清理（各实例的 cron 相互独立），其余实例的手动操作不受影响。

## 📦 安装与启用

### 作为独立插件使用

1. 将本插件放置于 `packages/plugins/@nocobase/plugin-attachment-cleaner` 目录。
2. 激活并安装插件：
   ```bash
   yarn nocobase pm add @nocobase/plugin-attachment-cleaner
   yarn nocobase pm enable @nocobase/plugin-attachment-cleaner
   ```
3. 在 NocoBase 管理后台左侧菜单即可看到「附件清理」管理控制台。
